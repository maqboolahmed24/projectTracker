# Local companion and optional office editor

The initial package targets Apple silicon macOS. Build with the reviewed Node 24 runtime using `npm run build:local-files`. The script bundles the local service and its dependencies, includes the Node runtime and licence notices, checks its help command, and writes `web/public/downloads/maqbool-local-mac.zip` plus SHA-256. These generated binaries are ignored by Git. Build the package on the Mac before building the Linux frontend image; its Dockerfile intentionally fails if the package is absent. The frontend serves it and `/local-files-help.html` from the same HTTPS origin. The package is not notarized; the customer guide uses standard macOS confirmation, not security bypasses.

Setup uses a native folder chooser and creates a persistent Ed25519 identity bound to the real selected root. It pins the cloud application's public signing keys obtained over its configured HTTPS origin. Repeat setup resumes partial configuration without replacing identity, root, origin or existing trust. After restore/revocation, New connection.command refuses to run while the helper is listening, asks for native confirmation, retires its old identity/connections in the private settings directory and requires fresh Owner pairing. It never changes the selected root or publication journals, and cannot revive the old cloud service registration. A different root requires a separately chosen state directory and new Owner connection. A localhost-only certificate is installed in the user's login keychain after normal macOS confirmation. Its 365-day renewal and removal are documented in the packaged guide.

The service binds only loopback: browser HTTPS on 3411 and private document callbacks on 3412. Requests require an exact configured cloud Origin, Host and JSON media type. Project pairing uses an expiring Owner-signed challenge, local one-time code and service proof. Browser connection tokens are held in memory; local configuration remains mode 0600 under a mode 0700 settings directory. Cloud revocation/current authority gates fresh 30-second publication/editor permits. Previewing and editing disclose plaintext to the user's own browser/computer, and do not create a cryptographic restriction against that authorised user copying it.

Publication uses descriptor-relative filesystem operations through Apple's Python 3, with a pinned root inode and no-follow traversal for every path component. The helper never follows a stored cloud path outside that root. It checks existing bytes, stages approved new bytes, captures previous bytes, installs without overwrite, records/fsyncs each stage, and verifies final bytes before issuing a receipt. Move/rename source absence and remove destination absence are checked as well. A changed file, symlink, missing parent, disk shortage or incomplete batch leaves a resumable conflict rather than a publication claim. Journals and previous bytes are local private data under `.maqbool-delivery`, retained for recovery; the initial release does not auto-delete these local backups. Disk admission includes a two-file allowance and 64 MiB reserve. Local operations and HTTP requests have finite bounds.

## ONLYOFFICE

The optional editor uses the official React wrapper 2.2.0 and an unmodified local `onlyoffice/documentserver:9.4.0` image pinned to `sha256:e3da62a847b9a5d51a11f73cfea1d9c13c3be3809614490d4edddcf01dcf919b`. Docker Desktop must already be available and appropriately licensed; no paid editor service is created. The community image is a separate AGPL installation; its original notices/branding remain, and compact controls use documented supported options. Source and terms: <https://github.com/ONLYOFFICE/DocumentServer>. Package notices cover bundled dependencies and Node separately.

Setup limits this container to 4 GiB and publishes only `127.0.0.1:3420`. The bridge validates signed, one-use edit permits and accepts at most two 30-minute memory leases. Word, Excel and PowerPoint Open XML documents must pass the same bounded format validation as managed uploads. Browser frames and assets are proxied over the companion's localhost HTTPS endpoint. Document source/callback capabilities are random; callbacks require the configured HS256 JWT and an exact document key. Output fetches are restricted to the local document server's cache paths, without redirects, with size/time limits. Documents containing automatic remote relationships or external spreadsheet data are refused; ordinary user-clicked hyperlinks remain. Plugins, macros, comments, chat, review, printing and editor downloads are disabled; supported compact toolbars remain. Unsupported or unavailable editing leaves ordinary external editing available.

The app's Save new version action requests a stable editor snapshot, verifies its hash, rechecks cloud authority and uses the normal encrypted immutable upload with the expected base version and stable retry IDs. An intervening file update fails safely. An ambiguous upload reply is recovered from the original operation/version rather than creating a duplicate. Sign-out closes browser leases and clears in-memory bytes; the separate editor may retain its normal temporary Docker cache, as explicitly documented. Removing the idle `maqbool-office` container clears that disposable cache; it must never be removed during a save.

## Focused acceptance

`test/local-files.test.ts` exercises real descriptor-rooted filesystem operations, crash-after-capture recovery, signed final receipts, unexpected edits, missing files, symlink/path escape rejection, move/rename/remove, forged/expired permits, editor replay and forged/remote callback rejection, and lease expiry zeroing. Four tests pass with the existing recovery policy/record tests (24 total).

`test/onlyoffice-integration.test.ts` is opt-in (`ONLYOFFICE_INTEGRATION=1`) and requires the isolated file-test PostgreSQL pair and the pinned local document server. It uses a real Chromium editor, explicitly grants normal local-network-access permission, edits a real DOCX, saves it as encrypted immutable version 2, decrypts/verifies the output, and confirms version 1 remains ready. The latest run completed in 15.53 seconds. This is local integration acceptance, not a claim that every customer has installed Docker or granted browser access. Chromium's permission prompt is explained in the product and guide. No public conversion service is used.
